The control loop

Nine steps, in order. Each one leaves a tenant-scoped record: the authorization decision, the execution result, the retest result, the evidence.

Discover→Identify→Map Reach→ Evaluate Policy→Decide→Authorize Execution→ Observe→Retest→Prove

Tamper-evident decision evidence, observed runtime outcomes, and retesting that closes the loop with proof rather than a status label.

How it works

Five steps from first email to an evidence pack your auditor can read.

1 · Scope call (30 minutes)What you run, which agents and MCP servers matter, what is out of bounds. You leave with a written scope and an exact price.
2 · Written scopeIn-scope systems, out-of-scope surfaces, environments, timeline, and the authorization statement. Nothing is touched before this exists.
3 · Connect, read-only firstAdapters attach with read-only credentials: inventory, identity, reachability. You provide credentials with the narrowest possible scope; we verify the path is live before claiming anything.
4 · Enforce & observePolicy is evaluated before sensitive tool execution. Every decision, execution and outcome is recorded — including the ones that fail.
5 · Retest & evidence packFixes are retested against the real condition, and you receive the evidence trail: decision, execution, retest, closure — in an export you can hand to an auditor.

About

Elitze Agentic Security is a product of TrueElitze Digital, built and operated by Terrell Hall in Victoria, British Columbia.

The product exists because of a specific gap: teams are now deploying agents that can call tools, read data and move money — and the only thing standing between an agent and a bad decision is often a dashboard label. Elitze narrows its commercial proof to the part that can be evidenced: which identity, reaching which capability, under which policy, with which recorded outcome.

Two rules shape everything here. First, the model is not the security boundary — identity, policy, authorization, execution controls and verified outcomes are. Second, missing evidence stays missing: no mock data, no synthetic telemetry, no placeholder success states. If a connector is not live, it says so.

FAQ

Do you need production access?

No. Reviews start against the shipped artifact (npm/PyPI package, repo, container) and configuration. Live validation happens only in an environment you nominate, with read-only credentials first and a written scope that names what may be touched.

What happens if the evidence is incomplete?

It stays incomplete and is labelled. Missing data resolves to UNKNOWN, UNMEASURABLE or INSUFFICIENT_REACH — never to a green check. A connector only reads INTEGRATED after a live authenticated path is verified.

Is this a replacement for Wiz, CrowdStrike or Defender?

No. Those cover cloud posture and endpoint telemetry at enterprise scale. Elitze covers the agent and MCP path: which non-human identity can reach which tool, what policy decided, and whether the decision is evidenced. It complements a CNAPP, it does not replace one.

How is the agent and MCP inventory collected?

Through provider adapters — MCP gateway/server discovery, GitHub and Actions, AWS IAM/CloudTrail, Microsoft Graph/Entra, and Kubernetes API/RBAC — using credentials you scope. Each collection is recorded so you can see what was read and when.

Do you support Google and GitHub sign-in?

The workspace is designed for SSO via Google and GitHub. Buttons on this page route to the workspace login; enabling a provider is a configuration step in the identity layer, done per tenant.

What about data residency and retention?

Hosting region, retention window and deletion terms are agreed in the scope before any data is ingested. Evidence exports are yours; you can request deletion at the end of an engagement and receive written confirmation.

What does it cost, and how do I pay?

Pilot $500 CAD (30 days, one control path) · Deployment $1,500 CAD · Enterprise custom. Payment by Interac e-Transfer or KOHO bank deposit; invoices are net 7. Google Pay becomes available once merchant processing clears.

My database isn’t connected — can we still start?

Yes for reviews, which work from the artifact. For the hosted workspace, a live control path needs DATABASE_URL, migrations and a verified tenant connection. Until then the product reports unavailable rather than pretending otherwise.

Can I hand the output to an auditor?

The evidence pack is built for that: decision, execution, retest and closure records with timestamps and tenant binding. It is not a certification and does not claim to be one.

What is the authorization boundary?

Nothing is scanned, probed or tested without written authorization and a defined scope. Unsolicited testing is not a service offered — to anyone.

The security boundary

The model or agent is not the security boundary. Identity, policy, authorization, execution controls, evidence and verified runtime outcomes form the boundary.

Scope discipline: written authorization first, always. No exceptions, no “just a quick scan”.
