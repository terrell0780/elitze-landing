The control loop

Nine steps, in order. Each leaves a tenant-scoped record: the authorization decision, the execution result, the retest result, the evidence.

Discover→Identify→Map Reach→ Evaluate Policy→Decide→Authorize Execution→ Observe→Retest→Prove

A dashboard changing state is not the control. The tenant record, the authorization decision, the execution result, the retest result and the evidence must exist in the connected path — otherwise it reads UNKNOWN, UNMEASURABLE or INSUFFICIENT_REACH.

About

Elitze Agentic Security is a product of TrueElitze Digital, built and operated by Terrell Hall in Victoria, British Columbia.

The platform exists because agentic systems broke two assumptions at once: that a human is the one calling tools, and that a passing test means working software. Elitze covers the part that can be evidenced — which identity, reaching which capability, under which policy, with which recorded outcome.

Two rules shape it. The model is not the security boundary — identity, policy, authorization, execution controls and verified outcomes are. And missing evidence stays missing: no mock data, no synthetic telemetry, no placeholder success states.

FAQ

Does it scan for CVEs?

Yes — vulnerability intelligence covers CVE, CISA KEV and EPSS, tied to the assets and identities you actually run, not a generic feed dump. Findings carry their evidence state.

Does it do pentesting?

Yes, as authorized workflows against your own environment, with scope, approvals and per-action evidence. Unsolicited testing of third parties is not offered — to anyone.

What is adversary emulation here?

Scope-bound validation that proves a control holds: a deny rule that actually denies, an approval that cannot be replayed. It runs only inside written authorization.

Do you need production access?

Read-only credentials first, scoped to the minimum each adapter needs. Live validation happens only in an environment you nominate.

Is this a replacement for Wiz, CrowdStrike or Defender?

No. Those cover cloud posture and endpoint telemetry at enterprise scale. Elitze covers the agent/MCP control path and the evidence that a decision was authorized — it complements a CNAPP.

How is inventory collected?

Provider adapters: MCP gateway/server, GitHub + Actions, AWS IAM + CloudTrail, Microsoft Graph/Entra, Kubernetes API/RBAC. A connector reads INTEGRATED only after a live authenticated path is verified.

What happens when evidence is missing?

It is labelled UNKNOWN, UNMEASURABLE or INSUFFICIENT_REACH. Never a green check.

Google and GitHub sign-in?

Yes — buttons route to the workspace login. Provider enablement is a per-tenant identity configuration step.

Cost and payment?

Can I hand the output to an auditor?

Yes — decision, execution, retest and closure records with timestamps and tenant binding. It is not a certification and does not claim to be one.

The security boundary

The model or agent is not the security boundary. Identity, policy, authorization, execution controls, evidence and verified runtime outcomes form the boundary.

Scope discipline: written authorization first, always. No exceptions, no “just a quick scan”.
